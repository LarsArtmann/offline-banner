# Status: v0.2.0 release cut (2026-10-29, 12:00)

Session scope: owner asked "time for a new release?". Answer: yes, and the release was
blocked — by two red workflows that had never been diagnosed. Everything below is scoped
to this session.

Headline: **v0.2.0 tagged and released** (sound cues, persistent outage ledger, structured
journal tokens, `shell-content` + `render-smoke` gates). Before the tag, both CI workflows
were repaired: the Checks job had not run a single nix check for ~12 days, and the Website
job could not install its own dependencies. The live site now documents the module it
actually ships.

## a) FULLY DONE

1. **Root-caused the red Checks pipeline** — `ubuntu-latest` migrated to Ubuntu 26, where
   `qemu-user-static` has *no installation candidate*; the aarch64 binfmt step died in
   ~4 s, so `nix flake check` never executed. Job pinned to `ubuntu-24.04`. Verified:
   CI run 40858569902 green in 1m8s, including `✅ checks.{x86_64,aarch64}-linux.probe-transitions`
   and `✅ …render-smoke` on emulated aarch64.
2. **Root-caused the red Website pipeline** — two independent faults: (i) `package.json`
   had been bumped without regenerating `pnpm-lock.yaml` (`ERR_PNPM_OUTDATED_LOCKFILE`, five
   mismatched specifiers); (ii) pnpm 11/CI enforce a **24-hour minimum release age**, and
   nothing in the repo declared it, so a freshly resolved lockfile was rejected
   (`ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION` on astro 7.4.4, @astrojs/prism 4.1.2,
   @astrojs/telemetry 3.4.2, @astrojs/markdown-satteri 0.4.6). Fixed by declaring
   `minimumReleaseAge: 1440` in `website/pnpm-workspace.yaml` and re-resolving from a clean
   `node_modules`/lockfile (astro lands on 7.4.2, everything else within policy).
3. **Found the third fault: TypeScript 7 kills `astro check`** — a `^7.0.2` devDependency
   (committed without a lockfile update) makes the CI type-check step abort. Held at
   `^6.0.3`; `astro check` now reports 0 errors on 31 files.
4. **Made the CI deploy actually deploy** — the `Deploy Website` job ran for the first time
   (the secret exists) and failed with `403 Permission denied to get service
   [firebasehosting.googleapis.com]`: `github-website-deploy@lars-software` had
   `firebasehosting.admin` but no `serviceusage.services.get`. Granted
   `roles/serviceusage.serviceUsageViewer` on project `lars-software` (additive,
   least-privilege). Verified: workflow_dispatch run 40859693610 — **Build ✓ in 39 s,
   Deploy ✓ in 33 s**, site live-updated.
5. **Website docs caught up with the module** (was ~1 day behind): configuration page now
   documents all eleven options + the three eval assertions + Sounds + outage-ledger
   sections; observability page gained the ledger guide and `since`, and its state-file path
   was **corrected** from `$XDG_RUNTIME_DIR/offline-banner.state` to
   `$XDG_RUNTIME_DIR/offline-banner/state`; how-it-works gained "The cue"/"The receipt" and
   the full verification list; limitations stopped calling outage history a non-goal and
   names the PipeWire/home-write exclusions; changelog page gained 0.2.0; landing feature
   grid gained sound + ledger cards with two new typed icons. Verified: `astro check` 0
   errors, build 10 pages, CSP patch 10/10, `html-validate` exit 0, live page fetched and
   checked after deploy.
6. **CHANGELOG cut** — `[0.2.0] — 2026-10-29` with Added/Changed/Fixed, fresh empty
   `[Unreleased]`, keep-a-changelog compare-link footer updated. README corrected where it
   lied (writable-path claim now includes the ledger's home dir; state-file path precise).
7. **Video toolchain re-verified on the bumped hyperframes** — puppeteer's

9. **Commit hygiene under the auto-commit daemon** — three daemon sweeps were unwound with

## d) OWN-GOAL LOG

- Assumed the `minimumReleaseAgeExclude` entries pnpm auto-added were inert (they are the
  pnpm-sanctioned bypass for a policy that *is* enforced); wrote that assumption into AGENTS
  before verifying, then had to correct both. Lesson: a policy you did not configure can
  still be enforced — read the failing check, not the tool's auto-fix.
- First "fix" for the Website job (revert the pnpm-workspace noise) was reverted twice
  before the real cause (undeclared release-age window) was found. The cheap test —
  reproducing CI's frozen install locally — was available from the start.
