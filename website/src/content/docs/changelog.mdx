## 0.2.2 — 2026-11-18

The DNS leg learns to distrust synthesized answers, and the smoke test
becomes safe to run beside a live banner.

- **DNS leg answer validation (behavior change)** — the leg used to accept
  any `getent` answer, so a resolver answering from a DNS blocker's zero-IP
  block page (or a split-horizon zone) kept it up forever with no packet
  leaving the host — live-verified: the default probe name sits on a DoH
  blocklist and resolved to a block page from local config alone, making the
  offline phase unreachable on that host. Private, loopback, link-local,
  unspecified and empty answers now count as DOWN, and a new `leg-contract`
  flake check EXECUTES the probe against a stub `getent` (block page,
  RFC1918 bounds, loopback, link-local, NXDOMAIN → fail; public → ok).
  **Upgrade note:** hosts whose `dnsProbeName` sits on a DNS blocker will
  now see real outages — that is the fix working.
- **`nix run .#smoke` crash fixes + namespace isolation** — the 0.2.1
  transient died on first use (three latent argv bugs, all invisible to
  structural greps), shared the live unit's runtime dirs (state overwrite +
  stop-time deletion orphaning the live unit), and silently ran on QML
  defaults because its props read a nonexistent attrset. It now runs on its
  own `offline-banner-smoke` dirs (safe beside a live unit), carries the
  unit's real environment (hardened PATH, cache home, ledger env), stays
  sound-silent unless `OFFLINE_BANNER_SMOKE_SOUND=1`, and every shape is
  pinned by execution-level gates.
- **State-file writer stages through a pid-unique temp** — concurrent
  writers can no longer tear a state write.
- Dependency currency: demo video re-rendered under hyperframes 0.9.52
  (20/20 WCAG AA contrast re-verified), starlight 0.43.1.

## 0.2.1 — 2026-11-18

The banner learns which limb is numb: reachability stops being one boolean.

- **Four independent probe legs + the phase ladder** — icmp (the original
  ping) is joined by a tcp leg (raw connect, IP literal, different anycast
  provider) and a dns leg (`getent`, the resolver applications actually use).
  A leg down while others are up is **degraded**: a silent info strip naming
  the down legs, auto-fading after `degradedDwellSeconds` — no alarm, no
  ledger. The yellow offline alarm now means a genuinely unusable network.
  Born live: one host's gateway policed ICMP so hard a single-leg banner
  cried offline 206 times in 8 hours over a usable network. Live-proven over
  a full week of real traffic: 1502 flap episodes all stayed silent-blue;
  every yellow alarm carried all-legs ledger receipts. Additive state keys
  (`phase`, `legs`, `degradedLegs`, `degradedVisible`) ride the state file
  and journal; a reference waybar consumer renders the ladder, pinned by 12
  fabricated-state fixtures and an outage-age widget ("offline 4m").
- **The banner can no longer be killed by its own ledger** — the ledger's
  `ReadWritePaths` hole was provisioned by nothing: on hosts without the
  directory, systemd failed mount namespacing (exit 226) and the banner was
  silently absent through every outage. The unit now provisions its ledger
  directory (`StateDirectory=`), and bad `historyPath` shapes fail at eval
  time instead of dying silently at runtime. Live-verified on systemd 261;
  a boot-level VM test (`vm-smoke`) guards the class.
- **The degraded strip cannot flash** — CI caught a re-show of a faded
  strip on an unchanged down-leg set; the re-arm now decides on the raw
  leg set instead of the UI framework's change signal, and the journal
  records every re-arm decision.
- **PATH-phantom gate** — the first live deploy of the legs shipped a unit
  PATH whose `getent` did not exist and every name-grep check stayed green
  while the dns leg failed every probe. The module-contract check now
  RESOLVES `timeout`/`getent`/`ping` against the rendered PATH.
- **CI honesty** — state writes are atomic (tmp + rename); the
  probe-transition harness drains orphaned state writes between scenarios,
  polls state reads, resets its control files, and drives the second
  provisioned ledger shape end-to-end; a `--print` dry-run exists for the
  smoke transient, whose props file was also fixed to be readable at
  runtime. Sound failures surface in the unit journal.\n\n## 0.2.0 — 2026-10-29

The banner learns to speak and to remember.

- **Sound cues** — one synthesized cue per outage transition (never per probe),
  a lower droop for link loss than net loss, a sparkle on recovery. Three
  build-time themes (`chime`, `droplet`, `retro`) with no audio assets, plus
  `soundTheme`/`soundVolume`; `"none"` for silence.
- **Persistent outage ledger** — one JSON line per completed outage in
  `~/.local/state/offline-banner/history.jsonl`, so outages outlive reboots.
  `enableHistory`/`historyPath`; blips, open outages, and demo runs never write.
- **Structured journal tokens** — `banner state=…`, `probe ok|failed`, and
  `outage ended from=… duration=…` are now the stable, grep-able surface. The
  state file gained `since` (current outage start).
- **New checks** — `render-smoke` proves the strip's pixels in headless sway,
  and `shell-content` asserts the built QML keeps its namespace, env seams, and
  the full synthesized WAV matrix.
- A reference waybar consumer (`contrib/offline-banner-waybar`), a project
  website, and a 24 s demo video.

## 0.1.0 — 2026-10-17

Initial release: `services.offline-banner` NixOS module with v3 behavior —
static yellow top-strip on every monitor, carrier-glob + ICMP probe (not
`nmcli`), 2-failure debounce, top-layer push-down animation, last-online
caption, click-to-dismiss, demo mode, structured journal lines + JSON state
file, systemd sandbox hardening (contract-checked line-by-line), and six flake
checks including a probe-transition machine test.

See the [full changelog](https://github.com/LarsArtmann/offline-banner/blob/master/CHANGELOG.md)
for the Fixed and Security sections.
