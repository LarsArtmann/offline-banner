# offline-banner: Agent Guide

Yellow top-strip offline banner for NixOS desktops — `github:LarsArtmann/offline-banner` (public repo created and pushed 2026-10-16).

## Identity

- One NixOS module, one file: `module.nix` (`services.offline-banner`, systemd **user** service, second-Quickshell-instance pattern — Quickshell runs the inline `shell.qml`; no dependency on any bar/shell plugin).
- Extracted from SystemNix 2026-10-16 (`modules/nixos/desktop/offline-banner.nix`, deployed there as gen 904 v1 — verified 2026-10-17: SystemNix live-session report anchors `/run/current-system == 904` + `system-904-link`; gen 904 shipped v1, v2/v3 were demo-proven only and ride SystemNix's next switch). SystemNix is the origin of every behavior doctrine (non-flashing yellow, debounce, fail-visible probe, push-down animation) — the rationale comments in `module.nix` are the contract; do not silently drop them when refactoring.

## Hard rules

- **The module stays single-file and self-contained** (QML inlined via `pkgs.writeTextDir`). Extracting the QML into a store file is allowed only if the env-var contract below survives unchanged.
- **The `OFFLINE_BANNER_{INTERVAL,PROBE_HOST,PROBE_TIMEOUT,FAILURES}` env vars are a public surface** (live-tuning via drop-in, demos, the pending VM test's probe injection). Renaming them breaks live systems. The leg additions (2026-11-09) — `OFFLINE_BANNER_TCP_HOST/TCP_PORT/DNS_NAME`, `OFFLINE_BANNER_DEGRADED_DWELL` — and the sound/history additions (2026-10-28) — `OFFLINE_BANNER_SOUND_THEME/SOUND_VOLUME/SOUNDS`, `OFFLINE_BANNER_HISTORY` — are the same contract class: unit-managed env, asserted by `module-contract`; when UNSET (bare `quickshell -p`, tests, demos) the QML keeps both features inert (silent, no home writes). Same class: `OFFLINE_BANNER_STATE_DIR` (2026-11-18 smoke-isolation — renames the state DIR under XDG_RUNTIME_DIR, name only never a path; unset → `offline-banner`, byte-identical old behavior; marker-asserted by `shell-content`, end-to-end by a `probe-transitions` seam scenario). App-only sibling contract: `OFFLINE_BANNER_SMOKE_{PROBE_HOST,DEMO,SOUND}` tune the `nix run .#smoke` transient (sound silent unless `SMOKE_SOUND=1`).
- **Never embed shell/JS parameter expansion (`${`-style) or a literal `''` in the inlined QML or check scripts** — Nix's lexer silently corrupts the former (observed 2026-10-28: `${n:-0}` in a check script rendered as `n:-0` with NO eval error) and the latter terminates the indented string outright. Escape as `''${` where a literal is truly needed; prefer POSIX-safe guards.
- **Nix '' string escaping**: the QML lives inside a Nix indented string — `\"` sequences in the probe JS are literal and required; there must be no `${` in QML/JS except intended Nix interpolations (`${cfg.layerNamespace}`). Same family: a heredoc emitted from a Nix string MUST use a quoted delimiter (`<<'EOF'`) or the build sandbox's shell strips `$@`/`$1` at write time, silently; multi-repo work passes ABSOLUTE paths everywhere (externals resolved the same relative path against different cwds — jq read one repo's lock while grep read another's, 2026-11-18); and where the tool shell blocks `systemctl`, busctl D-Bus calls are the substitute (`Manager.RestartUnit ss <unit> "replace"` — Stop needs the mode arg, empty fails `Job mode invalid`). Full write-ups: crush-config `references/lessons.md` (committed b40bb36).
- 2-space indentation; `nix fmt` (treefmt: nixfmt + statix) is the ONLY style arbiter and covers `.nix` only. Markdown is hand-formatted by deliberate decision (2026-10-17): status/planning docs are point-in-time snapshots, never machine-reflowed; no dprint.json in this repo (dropped as an uninvoked split brain — readopt only via a real BuildFlow `.buildflow.yml`, which regenerates its own config). SOURCE OF THE ZOMBIE FOUND (2026-11-05): BuildFlow auto-generates dprint.json in any repo it scans that lacks a `.buildflow.yml` (its preflight even warns about the remote plugin fetches) — a re-drop WILL resurrect on the next BuildFlow run here; killing it for good means adopting a real `.buildflow.yml` (D4, owner) or teaching BuildFlow to skip non-managed repos. **D4 DRAFT DECISION (owner-ready, 2026-11-18, per the buildflow skill's coverage model): adopt a minimal `.buildflow.yml` with the formatter steps SKIPPED and a rationale** — coverage (any `.buildflow.yml`, even skip-only) is exactly what stops the auto-generation, the skip list is project-owned policy (this repo: nix-only treefmt via `nix fmt`, markdown hand-formatted by decision, no prettier/dprint), and the flake keeps `nix fmt` as the dev-loop formatter (BuildFlow's format step stays skipped by policy; do NOT install its pre-commit hook). Cost: one small config file + periodic review when auto-configure evolves. The fleet-wide fix (BuildFlow skipping non-managed repos by default) is an upstream BuildFlow development task — file it there as the follow-up so every non-covered repo stops growing zombies; until it ships, each scanned repo needs its own skip-only `.buildflow.yml`.
- `probeTimeoutSeconds < checkIntervalSeconds` is an eval-time assertion — keep it.
- **Resolve, don't grep, the rendered unit PATH** (the PATH-phantom class, 2026-11-10): any check claiming "tool X is available to the unit" must RESOLVE X against the rendered PATH (`PATH=<extracted> command -v X` in a runCommand over the unit text file), never grep the unit text for the tool NAME — the unit PATH carried `pkgs.glibc` for getent, this nixpkgs ships getent as its own package (`pkgs.getent`), and the dns leg failed every real probe for a day while every name-grep check stayed green (the probe seams stub the whole script, so nothing executed it). `module-contract`'s PATH-phantom gate is the pattern; negative-tested at both layers (drop the package → string assert fires; keep a name-bearing but binary-less PATH → execution gate fires).
- **Recompute leg state from raw counters inside change handlers and `emitState`** — chained `var`/computed bindings read STALE mid-cascade (CI-proven 2026-11-10 on emulated aarch64: one state write carried `phase:"degraded"` + `degradedVisible:false` together). `rawDownLegs()` is the only truth for leg state; bindings render, functions decide. 2026-11-18 extension of the same doctrine: even a var-binding's CHANGED-SIGNAL is not contract-truth — CI (emulated aarch64) caught a degraded re-show on an unchanged leg set because the signal fired without a real set change; the degraded re-arm now compares the raw set (`lastDownLegsKey`) and suppresses same-content firings (d3be7bf). Signals deliver; raw state decides.
- **Journal asserts: exact counts only at deterministic positions; state-file reads always poll** — an exact `failures=N/2` grep is deterministic ONLY from a controlled start (fresh instance, single failing leg, monotone per-probe counters); past that, assert the TRANSITION (`assert_journal_re`, reason + counter-advanced). The state file is written by a spawned `sh` — a single read after a journal match is never evidence (it can lag the line AND catch the file mid-rewrite; the empty-file tear was CI-proven x86_64 2026-11-10 before the atomic tmp+mv write): poll via `assert_state_jq`/`assert_state`.

Three pnpm rules learned the hard way (2026-10-29): **any `package.json` bump must regenerate `pnpm-lock.yaml`** — CI installs with a frozen lockfile and dies on a manifest/lock mismatch (`ERR_PNPM_OUTDATED_LOCKFILE`), which is how the Website workflow sat red for two weeks. **`minimumReleaseAge: 1440` is declared in `website/pnpm-workspace.yaml`** because pnpm 11/CI enforce a 24 h age gate: resolve locally under it (`pnpm install` picks the newest old-enough version) and never hand-write `minimumReleaseAgeExclude` entries to smuggle a just-published package past the gate. And **TypeScript stays on 6.x**: `astro check` is a CI step and refuses to run against TypeScript 7 (`astro check does not currently support TypeScript 7.0`), so a `^7` bump in devDependencies silently removes type-checking from the gate. If a resolution goes bad, `pnpm clean --lockfile` runs package.json's `clean` script instead of the builtin — remove `node_modules` + `pnpm-lock.yaml` (via `trash`) to force a genuinely fresh resolution.

### Live smoke test (hardened unit without a NixOS switch)

Runs the exact serviceConfig sandbox as a transient user unit. Bus-transient properties do NOT expand specifiers (the `%t` expansion above is unit-file-only), so runtime paths are literal. The transient therefore cannot exercise the `%h` ledger hole at all — and unit-verify cannot see its runtime failure — so only a real unit start proves provisioning (that blind spot shipped the 2026-11-05 crash loop). Prefer the versioned form, which closes the hole: **`nix run .#smoke`** derives every property from the rendered serviceConfig and substitutes `%h`→`$HOME`/`%t`→`$XDG_RUNTIME_DIR` (override the probe with `OFFLINE_BANNER_SMOKE_PROBE_HOST=192.0.2.123`, force-show with `OFFLINE_BANNER_SMOKE_DEMO=1`, audition cues with `OFFLINE_BANNER_SMOKE_SOUND=1`). Since smoke-isolation it runs on `*-smoke` dirs, so it is SAFE beside the live unit (no shared writable namespace; its stop cannot orphan the live unit's binds). The hand recipe below stays for reference. Ground-truth store QML dir: extract exactly as `scripts/capture-demo.sh` does (third word of the eval'd `ExecStart`).

```bash
uid=$(id -u)
systemd-run --user --unit=offline-banner-smoke \
  -p ProtectSystem=strict -p ProtectHome=read-only -p PrivateTmp=true \
  -p RuntimeDirectory="offline-banner quickshell" -p RuntimeDirectoryMode=0700 \
  -p ReadWritePaths="/run/user/$uid/offline-banner /run/user/$uid/quickshell" \
  -p MemoryMax=256M \
  -p Environment="OFFLINE_BANNER_PROBE_HOST=127.0.0.1" \
  -- quickshell -p "$qml"
```

Checklist: unit active under the full sandbox; ping works with cap_net_raw (`probe ok` for 127.0.0.1); forced outage (restart with `OFFLINE_BANNER_PROBE_HOST=192.0.2.123`) → journal `banner state=shown reason=net` + `{"active":true}` in `$XDG_RUNTIME_DIR/offline-banner/state`; demo control (`OFFLINE_BANNER_DEMO=1`) → `{"active":true,"demo":true}`; RSS well under MemoryMax; fontconfig cache warnings gone (XDG_CACHE_HOME lands in the runtime dir). Transient runs carry NO sound/history env → both stay inert; to hear the cues live, add `-p Environment="OFFLINE_BANNER_SOUND_THEME=chime"` plus `OFFLINE_BANNER_SOUNDS` pointed at the extracted store dir. `systemctl --user stop` when done — RuntimeDirectory cleans up with the unit.

**Verified live end-to-end 2026-11-18 on evo-x2** (after fixing three latent runtime bugs, 41b3f49): the transient started, rendered the demo strip on the real monitor (grim rows ~50–110 ≈(239,217,169)), journaled `banner state=shown` demo:true, and stopped clean. Two live-session hazards recorded, one since FIXED: (1) **shared-runtime-dir hazard — FIXED by smoke-isolation (2026-11-18)**: the transient used to share the live unit's `offline-banner` runtime dir (state overwrite + stop-time deletion orphaning the live unit's namespace bind); it now provisions `offline-banner-smoke` (+ `OFFLINE_BANNER_STATE_DIR` seam) and injects `RuntimeDirectoryPreserve=true` for the shared-by-design `quickshell` dir.
